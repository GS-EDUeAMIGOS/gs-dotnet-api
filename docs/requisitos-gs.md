# Checklist — Advanced Business Development with .NET

## Fonte e interpretação

`2TDS Agosto - Global Solution 2026-2.pptx`, slides 22–28. Orientações gerais: slides 11–16 e 20; submissão: slides 81–85. A numeração é a posição real dos slides no PPTX, não o contador interno de cada disciplina.

Todos os itens abaixo permanecem pendentes. A documentação é uma síntese derivada, não transcrição integral nem promessa de nota. O PPTX contém notas editoriais e placeholders; consulte [pendências](pendencias.md) antes de tratar pontos ambíguos como definitivos.

## Requisitos e evidências

- [ ] **Slide(s) 23–24:** Desenvolver Web API ASP.NET Core 8 com controllers e domínio relacionado à solução CitizenTech.
- [ ] **Slide(s) 23–24:** Modelar pelo menos duas entidades relacionadas em 1:N, com validação dos dados de entrada.
- [ ] **Slide(s) 23–24:** Persistir no Oracle da FIAP com EF Core e provider Oracle; versionar Migrations.
- [ ] **Slide(s) 24:** Implementar GET lista, GET por id, POST (201), PUT (204) e DELETE (204) para cada entidade principal.
- [ ] **Slide(s) 24:** Retornar 400 com mensagem JSON para entrada inválida e 404 para id inexistente.
- [ ] **Slide(s) 27:** Manter projeto na raiz, repositório público, .gitignore sem bin/ e obj/ e Migrations versionadas.
- [ ] **Slide(s) 27:** Completar README com integrantes e RM, solução, diagrama de entidades e instruções de execução e teste.
- [ ] **Slide(s) 27:** Produzir vídeo de até 5 minutos no YouTube, público ou não listado, demonstrando CRUD e tabelas no Oracle.
- [ ] **Slide(s) 28:** Preparar demonstração do CRUD, modelo 1:N, Migrations, fluxo HTTP, erros e relação com Mobile/DevOps; domínio técnico do grupo.

## Condições gerais

- [ ] Relacionar solução ao tema CitizenTech, problema real e cidadão beneficiado (slides 3–7).
- [ ] Explicar ODS e contribuição às metas (slide 11).
- [ ] Confirmar grupo de até cinco integrantes, identificação e cadastro (slides 12–14).
- [ ] Confirmar instruções finais no Portal e submeter até 19/11/2026 às 23h55 (slide 14).
- [ ] Conferir acesso aos links e legibilidade dos materiais, sem segredos ou dados reais.
- [ ] Preparar a apresentação da disciplina conforme agenda confirmada.

## Formato específico de entrega

Um arquivo .txt no Portal do Aluno com RM, nome e turma dos integrantes, link do GitHub e link do vídeo (slide 27).

A orientação geral de .txt em .zip não deve sobrescrever automaticamente formatos específicos .txt/PDF: conferir exigência da disciplina e do Portal.

## Limites e observações

Swagger/OpenAPI, autenticação, arquitetura em camadas e testes automatizados não são cobrados nesta entrega (slide 23). Isso não equivale a proibir boas práticas justificadas.
